# Промпты — этап тестирования

**Инструмент:** Claude Code · модель **Claude Opus 4.8**.

---

### Промпт 1 — генерация тест-кейсов

```
Сгенерируй тест-кейсы для клиентского приложения картинг-центра по фичам F1–F4.
Покрой happy path и крайние случаи: скрытие прошедших/отменённых слотов, empty
state, гонку за последнее место (двойная бронь), поздняя отмена, отмена центром,
оценка только завершённого заезда, границы рейтинга 1..5. Для каждого кейса: ID, тип
(авто/ручной), шаги, ожидаемый результат.
```

### Промпт 2 — автотесты (Vitest + Supertest)

```
Напиши автотесты: доменные (domain.test.ts) на createBooking/cancelBooking/
rateBooking/listSlots и интеграционные (api.test.ts) на контракт через Supertest.
Проверяй коды ошибок контракта (NO_SEATS, ALREADY_BOOKED, LATE_CANCEL и т.д.).
Сбрасывай in-memory store перед каждым тестом.
```

### Промпт 3 — разбор упавшего теста (BUG-01)

```
Тесты падают с ReferenceError: Cannot access 'DAY' before initialization в seed().
Найди причину и предложи минимальную правку.
```

### Промпт 4 — разбор бага фильтра (BUG-02)

```
При выборе одного дня в фильтре список пуст, хотя заезды есть. Почему input
type=date + toISOString даёт полночь и как это ломает границу to? Дай минимальный
клиентский фикс без изменения контракта API.
```

## Как воспроизвести автотесты

```bash
cd app/server
npm install
npm test        # 31 тест, все PASS
```
