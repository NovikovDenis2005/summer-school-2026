# 2. Требования к MVP — User Stories

**Проект:** клиентское приложение картинг-центра «Апекс», роль **Клиент**.
Приоритизация по **MoSCoW**. Каждая история — с критериями приёмки.
Трассируется на решения из [1-elicitation/decisions.md](../1-elicitation/decisions.md).

Легенда статусов: 🟢 реализовано в MVP · 🟡 частично/заглушка · ⚪ бэклог.

---

## Эпик 1. Просмотр расписания

### US-01 · Список доступных заездов — 🟢 Must
> Как клиент, я хочу видеть список свободных заездов на ближайшие дни,
> чтобы выбрать подходящий по времени и трассе.

**Критерии приёмки:**
- По умолчанию показываются слоты на **ближайшие 7 дней** от текущего момента (R-027).
- Для каждого слота видно: дата/время старта, конфигурация трассы (короткая/длинная),
  маршал, число свободных картов, цена.
- Слоты, старт которых уже прошёл, в списке **не показываются**.
- Если доступных заездов нет — показывается **empty state** «Пока нет доступных заездов».
- Слоты отсортированы по времени старта по возрастанию.

### US-02 · Фильтр по датам — 🟢 Should
> Как клиент, я хочу отфильтровать заезды по диапазону дат, чтобы спланировать
> заезд дальше, чем на неделю.

**Критерии приёмки:**
- Есть выбор диапазона `from`–`to`; период может выходить за 7 дней.
- Пустой результат по фильтру → тот же empty state.

### US-03 · Детали заезда — 🟢 Must
> Как клиент, я хочу открыть карточку заезда, чтобы увидеть подробности перед записью.

**Критерии приёмки:**
- Видно: адрес центра и место сбора, длительность, конфигурация, маршал и его рейтинг,
  цена заезда, цена проката экипировки, число свободных мест, наличие фонда проката.
- Если мест нет — кнопка записи неактивна, показан статус «Мест нет».

## Эпик 2. Бронирование

### US-04 · Запись на заезд — 🟢 Must
> Как клиент, я хочу записаться на выбранный заезд, чтобы гарантировать себе место.

**Критерии приёмки:**
- При записи выбираю экипировку: **своя** (`own`) или **прокат** (`rent`).
- Вариант «прокат» недоступен, если прокатный фонд слота исчерпан (A-002).
- Сервер атомарно проверяет наличие свободного карта; при успехе бронь создаётся,
  число свободных картов уменьшается на 1 (R-004).
- Если мест не осталось (кто-то занял раньше) — запись **отклоняется** с понятным
  сообщением «Мест уже нет», список обновляется. Двойных броней быть не должно.
- Повторная запись на слот, который уже забронирован этим клиентом, **невозможна**.
- В брони зафиксирована цена заезда на момент записи (A-003).

### US-05 · Мои брони — 🟢 Must
> Как клиент, я хочу видеть свои записи, чтобы помнить, когда и куда мне ехать.

**Критерии приёмки:**
- Список моих броней со статусами: подтверждена / завершена / отменена мной /
  отменена центром.
- Для предстоящих — видно время до старта.

## Эпик 3. Отмена

### US-06 · Отмена брони клиентом — 🟢 Must
> Как клиент, я хочу отменить запись, если передумал, чтобы освободить место.

**Критерии приёмки (A-004):**
- Если до старта **> 60 минут** — отмена проходит, место возвращается в слот
  (свободных картов +1).
- Если до старта **≤ 60 минут** — отмена через приложение **запрещена**, показывается
  «Поздняя отмена невозможна, свяжитесь с центром» + телефон.
- Отменить можно только бронь в статусе «подтверждена».

### US-07 · Отмена заезда центром — 🟢 Must
> Как клиент, я хочу узнать, если центр отменил заезд (погода/форс-мажор), чтобы
> не приехать зря.

**Критерии приёмки (R-008):**
- Бронь получает статус **«Отменён центром»** с причиной, не удаляется из «Моих».
- Клиенту приходит **push**-уведомление.
- Повторная запись на этот слот **запрещена**.

---

## Эпик 4. Оценки

### US-08 · Оценка маршала — 🟢 Must
> Как клиент, я хочу оценить маршала после заезда, чтобы поделиться впечатлением.

**Критерии приёмки (A-005):**
- Оценка доступна **только** для брони в статусе «завершена».
- Шкала **1–5 звёзд** + необязательный комментарий.
- Одна оценка на бронь; повторная отправка **отклоняется**.
- После отправки оценка видна в карточке брони.
